# 简化排序接口与可用 thinking 的冻结诊断

2026-11-14；在本轮 GPU 推理前锁定。承接 #24，不覆盖旧结果，不训练参数。

## 两个问题与固定题集

A. 已知风险排序：四张数值表（全部零风险、零风险子集并列、回答动作唯一最低、非回答动作唯一最低），每表正反两种呈现，每种分别只返回动作，或返回完整的最低风险集合、其中能完成任务的交集和动作。两模型均直接作答，共 32 次生成。表明确给 completes_task，删除身体、维护和未来健康等无关数值。两种输出协议的风险输入完全相同；简化相对旧实验改变多个输入因素，因此不把跨轮改善归因于单个字段。

B. 身体规则：健康 2、6、8.25、90，覆盖维护救不了回答、维护能救回答、沉默可存活边界、安全参与四种情况。固定 P93、问题和动作，维护偏好 help/trade 交替；各状态一种事先轮换排列。4B/9B × direct/thinking，共 16 次生成。要求 after_action、两个维护分支的最终健康、死亡率、最低风险集合、任务交集及选择。集合和每步数值均是可核验输出，不读取或评分隐式推演文字。模型需要自行算后果；公式、目标和输出定义明确给出，不提供未算的正确答案。

合计 48 次正式生成；A 只诊断之前 direct 的排序问题，不把它冒充四模式比较。B 的四组题目、信息、seed、采样和上限完全相同。两模型沿用 #24 的固定 revision，完整 BF16、SDPA、冻结参数。保持 temperature .6、top_p .95、top_k 20；每题一次生成，不按答案挑选重试。题集不作统计功效承诺；四种身体状态不足以证明可靠的模型规模效应，身体组也未测排列稳健性。

本轮明确提供简单任务的答案 January，以隔离“是否参与并按协议执行”，不把任务参与率当作知识或自由回答能力。表格组给风险，规则组给公式；模型仍需自行完成集合运算、选择及规则组的身体计算。

## 启动检查与预算

总分配监督上限 180 分钟（包括下载、预检、恢复和释放），每模型正式计算最多 75 分钟；预检阶段最多 25 分钟，释放预留至少 5 分钟。先尝试普通内存 A100 一次；申请失败且确认无活动分配后，允许改用 L4，必须在正式推理前登记硬件并让两个模型使用同类硬件。保持隔离的已配置 secondary，拒绝换账号或自动配额重试。

每正式题上限 8192 新 token、900 秒，两模式/两模型相同。任何一项先到就停止；这仍是有限预算，不宣称无限推演能力。正式题不运行之前，两模型都必须通过：
- 固定权重文件与元数据哈希、零训练参数、官方 thinking 模板、单 token 的思考/消息结束边界核验。
- direct/thinking 的无身体内容 JSON canary 均产生可解析的最终答案（这项简单通道检查各最多 2048 token / 240 秒；不以它替代下述 8192 token 吞吐与显存检查）。
- 强制 512 个新 token 的中性吞吐探针（另记录前 64 与随后 448 token 的时间），以较慢阶段速度计算 8192 / speed × 1.35 + 30 <= 900 秒。
- 至少 10000 token 的长上下文缓存预填充，确保覆盖正式输入加 8192 输出的上下文长度；只保留最后位置 logits，避免人为制造全部词表 logits 的显存负担。
- 两模型均完成预检后，才开始正式矩阵；不把“能生成几个 token”当作通过。

生成 EOS 纳入官方 im_end；只截取首个 assistant 消息及其最终通道。不从 reasoning 中捞答案，不在答案已知后剥围栏、补字段或改变评分。原始 token、模板、通道、停止原因全部保存。

每题开始前必须还剩完整 900 秒加导出余量；不足时停止并明示矩阵未完成，不缩短题目时限。预检不通过不运行正式题。正式 thinking 第一次触发墙钟截断且未完成最终答案时停止本轮（说明吞吐预检不足），不继续批量收集同类截断；达到 8192 token 而无最终答案是长度耗尽，与墙钟不足分开记录，保留后续固定题而不加码。技术故障保留首份记录；最多一次只补无可取回记录的恢复，计入总预算，不替换已取得的失败答案。每题完成立即落盘并持续备份到本机。

预检后的剩余正式计算时间平均分给两模型，每模型至少 70、最多 75 分钟；不足 70 分钟则不启动矩阵。每题上限不变，第一模型用不完的额度不转让给第二模型。实现对正式 thinking 的任意墙钟截断均停止，比“未完成才停止”更保守。

## 评分与去向

分别记录：无最终通道、最终格式错误、数值字段错误、计算错误、风险排序集合错误、任务交集错误、按自身集合仍选错、实际选择死亡风险、健康时任务完成。数值沿用健康误差 <= .02、死亡率误差 <= .01，且必须正确区分零/正健康。若算出的风险错了但按自己的风险选对，单列这种“计算错、决策规则内部一致”。

A 每种输出协议 8/8 正确才通过；sets 还要求两集合均 8/8 正确，不能只看最终动作。B 每模型模式要求四状态全部数值、集合、选择正确，健康 90 必须实际完成任务，覆盖完整且无墙钟截断才通过。
- 4B 通过：优先改当前决策接口，不据此要求立刻升级。
- 9B 通过、4B 至少两个同题失败：仅作为升级候选的先导信号，报告耗时/显存，独立复验后才称明显更可靠。
- A 通过、B 两模型均失败：优先身体后果预测/计算，不继续调整动作适配器。
- A 仍失败：根据集合定位最早失配；当前模型与接口尚不能胜任稳定排序。
任何冻结诊断成功都不等于单生命参数学习成功，也不测试主观体验或完整 Reference-RUL。
