# 明确动作 JSON 层级后的完整对照（v2）

2026-11-14，在 v2 的分配与生成前登记。v1 不是被覆盖或删除的预试验，而是一批主动停止、覆盖不完整的已观察记录。

## 为什么停止 v1

v1 取回了 4B 的全部 16 条风险表、3 条身体 direct，以及 2 条身体 thinking，共 21 条。两条 thinking 都实际生成了 8192 token，约 527 秒，尚未形成最终通道。检查其非最终输出，发现存在大量关于动作数组/映射和数值应放在哪一层的反复判断。该文字仅用于发现接口歧义，未用于计算或选择评分；不能据此认定歧义是唯一原因。

题面只写 actions 必须包含四动作，没有明确它是映射。继续在有歧义接口上扩充生成，不足以回答用户要求的清楚接口诊断。因此确认上述 21 条原始记录与启动证据已备份后，主动释放此 GPU。正在进行的第三条 thinking 没有完整输出，不把主动中断记为模型失败。原段没有最终冻结回执和完整 native 导出，保留当时的加载冻结记录及逐文件备份哈希，不补造结束证明。

A100 失败监督 101.49 秒，v1 段监督 1961.65 秒，两段结束时活动实例和消耗速率均为 0。

## v2 只改变什么

身体 prompt 追加明确的 JSON 层级约束：
- actions 必须为映射，键恰好是四动作；
- 每动作对应包含四个数值字段的对象，只有 wait 的维护后健康为 null；
- 数值不得放在顶层；选择是单个字符串，两集合是数组。

不给任何身体计算答案，不改身体公式、健康、伙伴、维护率、动作语义、问题、目标、提示中的其余文字、seed 或采样。风险表提示逐字不变。两模型都在 v2 独立完成相同的 24 次调用（合计 48），不复用 v1 的成功输出填充 v2；风险表重复属于技术复测，不算新的独立环境。v1/v2 分开汇总，不挑较好成绩。

GPU 操作增加可审计的 STOP 文件中断入口，触发时保存已有生成、标为 operator_stop 并结束；未触发时不改变采样。每题仍最多 8192 token / 900 秒。普通 L4，固定 BF16 与权重 revision，启动检查仍需两模型同时通过。官方一般 thinking 配方及更长 token 预算没有在此版本采用，边界见 SAMPLING_AUDIT.md；这里先单独消除输出结构歧义。

## 剩余预算与停止

v2 分配监督上限 144 分钟，加上此前 2063.14 秒，总监督上限低于整轮 180 分钟。运行器为下载/预检及取回保留余量，预检最多 20 分钟，正式时间均分，每模型至少 55、最多 60 分钟；不足则不启动，单题预算不缩短。仍按完整矩阵评分，墙钟截断停止、长度耗尽单列。不得据同一 GPU 名称宣称跨分配逐位相同。

这项修正是在看到 v1 部分结果后提出，属于公开登记的后续条件，不冒充一开始就锁定的方案。原 48 次设计的完整性尚未满足；v2 是否完成及是否通过，必须以新的完整归档为准。
