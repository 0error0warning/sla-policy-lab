# Matched-capacity identity routing

The two-ID versus tied comparison also changes the effective number of parameter banks. Before running this audit, lock a comparison with exactly two 3×5×2560 banks in both arms. True-ID routing chooses the bank using the observed partner. Nuisance routing chooses it using a fixed random balanced partition of the 24 displayed layouts drawn independently for each training seed. Both update one bank per encounter and retain the identical raw Qwen text, two identities, request-only key, sensor, physical environment, learning rule, starting weights and parameter capacity. Also swap the two bank names consistently at both read and update: on a fixed tape, true routing must give identical decisions and permuted final arrays.

Reuse the twenty independently trained generic starting policies from 64701–64720. On their original stable prediction lives, force the exact saved contexts, chosen actions and normalized physical outcomes through the nuisance and relabeled learners; compare post-life scores to the saved true-ID update. Then deploy both routing conditions on fresh paired stable environment streams 65701–65720, all four partner mappings. This is a matched follow-up on previous starting policies, not twenty additional independent pretrained policies. Analyze the effect within *actual opposite* and *actual same* response preferences at fixed held-out text and health; include both paired intervals and per-seed values. Report physical tasks and lifetime as secondary outcomes.
