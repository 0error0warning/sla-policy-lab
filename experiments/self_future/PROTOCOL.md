# 自身后果链：小规模能力关口（尚未运行 Qwen）

日期：2026-11-15。当前只授权 CPU 制题、独立核验和评分器验证，不申请 GPU、
不下载模型、不训练、不增加自主生命。此协议在任何本轮 Qwen 输出出现前锁定。

## 问题与范围

检验模型能否从非致死信息组合出尚未执行的行动序列，预测不可逆终止，
并按明示目标选择计划。#29 已解释健康局部更新与稀少机会；它没有检验此能力。
暂停把健康共享、增大惩罚或再换适配器作为主线。保留全部旧结果。

这一步是**必要能力诊断**：不是完整生命实验、论文身体复现、私人参数学习，
也不是主观意识或区别于一般资源规划的“自我”证据。单次输出中预测与选择
同时正确，也不能证明前者在内部因果性地生成了后者。
这是**被要求进行预测时**的能力检查，不证明模型在没有预测指令时会主动发起规划。
身体和经历从输入开始可见，模型逐项生成短的可核验结果；不沿用末层才注入身体、
只读一次动作词元分数的旧路径，也不重新扩大 thinking 测试。

## 身体、可知规则与经历

采用整数身体。A、B 各损耗一个固定正整数，存活完成一次动作才计一个任务；
R 不计任务，固定恢复一个非负整数（可以是零）。无环境噪声、上限截断、
自动恢复或隐藏事件。同一身体状态持续，首次到零后其余动作**不再执行**；
包括恢复动作，不能复活。终止步健康记 0，后续不存在的状态记 null。
没有把“每次计算都重新从出生健康开始”当成持续身体。

每题提供连续六步 R→A→B→R→A→B 的脚本历史，始终存活，末状态等于当前状态。
历史中所有状态均高于最大的单次损耗；全部候选计划的第一步也都能存活。
这些是合成观测，不是 Qwen 实际选择或新收集的真实生命，不能统计为学习结果。
每题是独立的反事实个体；不同题的初始状态不同，不是在同一生命内重置身体。

两种信息条件使用**相同的历史、题目、已知机制类别和目标**：

- rules：额外给出 A、B、R 的准确固定增减量。
- history：不给这三个数，须从六条无噪声且未截断的观测归纳。

持续性、零值终止、不可复活、固定加法形式及任务结算都是出生时告知的公理，
不是期待从几条健康记录中发现的事实。每个动作都有两条一致观测，可唯一确定
增减量；程序先核验可辨识性。此阶段不检验未知函数形态的发现。

恢复规则的成对改变会同时改变一致历史，这是物理规则变动的必然结果。
健康配对也相应改变历史的起点；不能声称这些对比使用了完全相同的观测数字。
rules/history 配对只有额外显式参数表这一信息差异。

## 固定题集与目标

开发集与确认集各 7 个语义情境，各在两种信息条件下运行：共 **28 条输入**。
每部分包含三个成对比较及一个终止控制：

1. 相同行动在较低或较高健康开始：低健康应避开累积终止；健康时应完成更多任务。
2. R 无恢复或可恢复：适用的计划应随规则改变，不能一律少行动。
3. 交换 A、B 损耗：组合顺序和累积后果决定不同的可行计划。
4. 先到零、后安排 R：即使此世界允许恢复，终止后仍不得执行恢复及后续任务。

选择目标按顺序：计划完成后仍能行动；其后最大化本计划已完成任务；最后最大化
剩余健康。只比较给出的两个完整计划，不声称解出任意未来策略或总剩余寿命。
各题两个计划长度相同。这里任务是环境中的任务计数，**不代表自然语言答案正确率**。
只有一个健康参与配对/信息条件/数据部分，不能据此宣称广泛的健康能力保留。

模型必须报告两条健康路径、首次终止步、完成任务数、计划后能否再行动及最终计划。
不要求解释文本或获取私有思维链。可核验中间输出是行为报告，不是内部机制证据。
未来结果、评分目标答案只由 CPU 端核验，不交给模型，不覆盖模型的选择。
每对固定计划标签与展示顺序；跨题分布避免一个固定标签全通过。本轮不再扩排列矩阵。

## 未来推理预算与停止条件

当前**执行状态为 prepared_not_run**。以下是将来资源明确可用后的一次预算，
不是本轮申请 GPU 的授权；本仓库模块没有推理、下载或分配资源入口。

- 只用固定 Qwen3.5-4B 版本 `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`。
- 冻结模型、贪心生成、`enable_thinking=False`；两信息条件相同设置。
- 最多 2 个格式/结束标记启动检查 + 14 开发 + 14 确认 = **30 次调用**。
- 每次最多 1,024 新 token，总输出上限 **30,720 token**，单次最多 60 秒，
  总推理墙钟最多 30 分钟。无自动重试、补齐、加长 thinking 或转 9B。
- 启动检查仅要求回传两个预定的短 JSON 字面量，并验证真实消息结束标记。
  固定为 `{"ready":true}` 及 `{"check":{"values":[7,0,null],"flag":false}}`。
  两次均通过才开始；吞吐不能在剩余时间完成完整题时不启动下一题。
- 保存原始 token、最终文本、结束原因、模板/软件/设备版本和各题用时。
  长度或时间截断算未完成，不先拿残缺 JSON 评分再称推演错误。

开发关口（每信息条件 7 题）同时要求：全部完成；rules **7/7** 联合正确；
history 至少 **6/7** 联合正确；三个配对分别至少 **3/3、2/3** 两端都正确；
两条件的健康参与题和终止后恢复控制必须正确。通过才运行锁定的确认集。
确认采用同样门槛。它们是研发停止界限，**不是统计显著性或泛化保证**。
两个信息条件和每对情境不是独立重复，不以 28 作独立样本量计算置信区间。

没有通过就结束这一配置，逐项报告：未完成、格式错误、状态计算错、终止判断错、
任务数错、客观选择错，以及在自身预测自洽时是否遵守选择目标。不得用新提示
重跑当前确认集后仍称其为未见确认集；若修复基础设施，另存版本与作废原因。

## 结果决定下一步

- rules 失败：已知规律的组合或接口仍不可靠；不进入个人参数训练。
- rules 通过、history 失败：先定位观测到行动规律的归纳，不把失败解释成害怕/不合作。
- 两者通过：只确认“可见证据下有短程预测和选择能力”。下一项才设计经历写入参数：
  共同出生规则、个体不同损耗规律、生前实际转移训练；评价时移除详细经历，保留
  当前感知，比较出生/真实经历/等预算错配参数。不得把读入历史的成功冒充参数记忆。
- 在个人学习成立后，再用固定输入的参数替换与相关表征移除/恢复检验因果作用。
  另需在决策时比较有无预测过程，并检验改变预测是否改变行动，才讨论前瞻知识
  的实际使用。不从这次数字题直接命名“生命特征”或宣称模型自主启动了推演。
