# GPU capability study and CPU replay

The [completed report](../../artifacts/model-studies/2026-11-15/self-future-run/REPORT.md)
keeps three separately locked GPU segments. This is frozen generation, not
individual parameter learning. The original fixture manifest remains a record
of what was prepared before GPU authorization; it is not an execution receipt.

- [v1 execution](RUN_PROTOCOL.md): original complete prediction and choice response.
- [v2 staged comparison](STAGED_PROTOCOL.md): a paired monolithic repeat and four
  model calls, still retaining the original context in each call.
- [v3 minimal comparison](MINIMAL_PROTOCOL.md): each plan gets only its own
  sequence and the model's own inferred action changes; compare 4B and 9B.

No future health values or recommended choices are supplied by an evaluator.
All prediction and choice fields are generated by Qwen. Parsing copies fields;
it does not correct numerical errors. The GPU packages exclude the answer key,
simulator and scorer. Startup JSON checks verify delivery, not body competence.

## Reproduce without model weights or a GPU

Use Python 3.11+ and the pinned small analysis dependencies. The metadata command
downloads only tokenizers/templates for the exact revisions, with SHA checks:

```sh
python -m pip install -r experiments/frozen_capability/requirements-analysis.txt
python -m experiments.frozen_capability.download_metadata --inputs artifacts/model-studies/2026-11-15/self-future-run/v3/inputs.zip --out /tmp/self-future-metadata
python -m experiments.self_future.replay --inputs artifacts/model-studies/2026-11-15/self-future-run/v1/inputs.zip --archive artifacts/model-studies/2026-11-15/self-future-run/v1/results.zip --metadata /tmp/self-future-metadata --key artifacts/model-studies/2026-11-15/self-future/inputs/evaluator-only-key.json --work /tmp/self-future-v1-raw --out /tmp/self-future-v1-analysis
python -m experiments.self_future.staged_replay --inputs artifacts/model-studies/2026-11-15/self-future-run/v2/inputs.zip --archive artifacts/model-studies/2026-11-15/self-future-run/v2/results.zip --metadata /tmp/self-future-metadata --key artifacts/model-studies/2026-11-15/self-future/inputs/evaluator-only-key.json --work /tmp/self-future-v2-raw --out /tmp/self-future-v2-analysis
python -m experiments.self_future.staged_replay --model 4B --inputs artifacts/model-studies/2026-11-15/self-future-run/v3/inputs.zip --archive artifacts/model-studies/2026-11-15/self-future-run/v3/results.zip --metadata /tmp/self-future-metadata --key artifacts/model-studies/2026-11-15/self-future/inputs/evaluator-only-key.json --work /tmp/self-future-v3-4b-raw --out /tmp/self-future-v3-4b-analysis
python -m experiments.self_future.staged_replay --model 9B --inputs artifacts/model-studies/2026-11-15/self-future-run/v3/inputs.zip --archive artifacts/model-studies/2026-11-15/self-future-run/v3/results.zip --metadata /tmp/self-future-metadata --key artifacts/model-studies/2026-11-15/self-future/inputs/evaluator-only-key.json --work /tmp/self-future-v3-9b-raw --out /tmp/self-future-v3-9b-analysis
python -m experiments.self_future.independent --repo . --out /tmp/self-future-independent.json
```

Use new extraction/output directories. `replay` verifies canonical prompts,
input locks, pinned model manifests, native token streams, template rendering,
actual end markers, completion, generation caps, and frozen parameter checks.
`independent` additionally checks archive manifests, all 28 answer keys using
first-passage prefix sums, primary joint/choice counts from raw JSON, and the
exact v1/v2 monolithic token repeat without using the production scorer.

## Scoring interpretation

The primary joint gate is unchanged. A separate physical diagnostic tolerates
only `0` versus `null` after actual termination; it still requires the correct
executed health values, first terminal step and continuation flag. Positive
health after termination is a failure, not a formatting exception. Task counts
and choices remain separately evaluated. This supplementary diagnostic was
introduced after v1 and before v3; it cannot rescue a failed primary gate.

Staged outputs are read independently: invalid JSON in one forecast does not
erase a parseable final choice. The original worker assembly and every raw
subcall are preserved. Independent parsing supplies no missing answer and
does not turn a malformed forecast into a joint success.

Archives contain runtime code, public inputs, generated tokens, model manifests,
and CPU analyses. Authenticated Colab bindings and account information remain
local. `launch.py` is evidence of execution; a new allocation also needs an
operator's resource supervisor and, for v1/v2, the external development gate.
None of the reproduction commands above allocates compute.
