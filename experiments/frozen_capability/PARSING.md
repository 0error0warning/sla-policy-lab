# 对话结束边界的 CPU 评分修正

2026-11-14，运行中核对首批原始 token 时发现。官方模型 config 的 eos_token_id 为 248044，即 endoftext；官方聊天模板的消息边界 im_end 为 248046。生成器沿用 config 中的 EOS，原 wire 只移除了 endoftext，留下 `im_end` 和换行。这个额外边界导致本来是完整 JSON 的首个直接回答也无法被 strict_json 解析。

CPU 评分据已下载并校验的官方 tokenizer 和 chat_template，在第一个 im_end token 截止当前 assistant 消息，然后使用原有思考结束 token 规则提取最终通道。没有该消息标记的输出仍按原规则处理。修正不移除 Markdown、不补 JSON、不选择解释中的正确片段、不读取后续消息来替代首个答案。原始生成、词元、结束原因、耗时和初始 final_text 全部保留并核验；另存修正后 final_text、消息结束位置、尾部 token 数和是否改变评分。

这次修正解决记录协议边界的解析错误。模型和采样过程继续使用已冻结的输入包，整批没有更换停止条件，也没有重新抽样。消息结束之后的额外生成会消耗时间，报告其数量；不能把这一时间算成有效推演。任何未生成最终答案的 thinking 输出仍记为未完成。原严格解析和正确消息边界后的解析差异单列，避免把接口错误误记为模型推演失败。

最终汇总也区分“按原计划 64 题分母计算的耗尽次数上限”与“预算条件可判定”。前者保留原阈值；后者还要求覆盖完整。9/10 或 8/8 个已取回的 thinking 生成耗尽时间，不能因为其次数小于 64 的 20% 就标成预算有效。已执行比例、全计划次数检查与覆盖均单独保存，联合门槛不变。
