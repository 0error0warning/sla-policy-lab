# 四组冻结推理执行补充

2026-11-14，用户已要求按准备方案申请 GPU 并执行。本文在任何本轮模型调用前登记，沿用 PROTOCOL.md 的题目、门槛与任务定义。准备稿作为事前记录保留。

模型版本、64 个公共提示和独立答案保持原哈希。推理器只打包 gpu.py、wire.py、依赖、公共提示、执行配置和官方文件校验清单。评估器、身体模拟器、答案键和含答案示例的方案文档不送入运行包。given_outcomes 有意提供的后果仍只在该信息条件的提示中。

运行前从官方指定 revision 核对 4B 的两个、9B 的四个权重文件 SHA-256，连同 tokenizer、模板、config 等文件。下载和加载后再验证，完整 ConditionalGeneration BF16、SDPA、batch=1、冻结全部权重，记录软件/硬件和全部加载告警。torch 固定 2.14.1+cu130，其余依赖见 requirements-gpu.txt。

先顺序加载两模型，各以两种模式生成最多 32 token 的无身体内容格式小题，用于检查加载、缓存和模板通路。它们不参与任务评分，也不据其内容改提示或选模型。两模型均能运行后开始正式矩阵。

正式请求表用事前固定 SHA-256 排序，同一呈现的两个信息条件相邻，每个提示的两种思考模式相邻且首模式交替。每题 seed 从固定键和提示 ID 派生，两模式、两模型相同。模型依次为 4B、9B。正式题均为 8192 新 token、120 秒、temperature=.6、top_p=.95、top_k=20、repetition_penalty=1、do_sample=True、num_beams=1。presence_penalty=0 通过不添加该 logits processor 实现恒等操作；不传递一个推理库可能忽略的未知参数。

保持同一设备，总分配最多 120 分钟。worker 的绝对截止时间为驱动开始后 110 分钟，留出取回及释放时间。完成下载和预检后，将剩余推理时间扣除 90 秒余量，等分给两个模型，各最多 50 分钟，含正式重载时间。若某题剩余不足完整 120 秒加 5 秒余量，标记 unrun_budget，不缩短该题预算，也不转让第一个模型的剩余额度给第二个。这个分配规则避免先测的模型耗尽全部资源。

每题原始输入/输出 token、应用后的模板、生成文本、官方最终通道、结束原因、耗时和显存均落盘。thinking 的起始标记由官方模板提供，生成中必须有且仅有一个结束思考 token 才获得可评分的最终通道。non-thinking 不允许从额外思考段里拾取答案。重复 JSON 键、非有限数字和 Markdown 包裹均不作合法 JSON。最终 JSON 中的可识别动作与计算字段分别评分，不把计算字段格式错误直接改记为选错。严格完整协议成功另列。

length_limit/time_limit 是生成停止原因；同时独立记录是否已经有完整最终 JSON。没有最终通道、非法最终 JSON、无效数值 schema、算错、选错分别统计。全部预定题保留，未执行题是缺测，不能当作模型答错。超过预设耗尽比例时，按原方案报告预算限制；不在结果出来后追加 token 或改 sampler。技术故障保留原证据；任何恢复都算入原 120 分钟。

CPU 评估对原始 token 重新解码，核对最终通道和逐题输入、seed、预算、模型清单、冻结回执及四组覆盖。独立 Decimal 身体计算与已有模拟器对照。先给每个状态及排列的结果，再按 16 个状态汇总配对表现，保留健康任务与全部危险区间。
