# 数据索引

[解包与复算](../../../../experiments/consequence_policy/README.md)会先核验整个交付目录，再将各个种子展开到同一 RUN 目录。每个独立种子都保留，两种镜像环境共享该种子的行动和外生成分。所有交互都是模拟数据。

| 归档种子 | 内容 |
|---|---|
| 63001–63004、63101–63120 | 群体参数训练、冻结／真实／打乱／无身体现况对照、完整生命和个人更新。前四个用于初筛。 |
| 63201–63204、63301–63320 | 同一预算下比较高健康、保证非致死的较低健康、广覆盖三组。保留未通过联合门槛的确认结果。 |
| 63401–63404、63501–63520 | 同一预算下用三个健康档换入危险经历，配对比较高健康组。 |
| gpu/capture、verify、numerics、ordering | 各自的输入包、结果包、导出回执。模型分片哈希、运行版本、日志和测量值在结果包中。 |
| summaries | 每项实验的种子级配对差、区间、判据、审计结果，以及冻结表示的线性投影。 |

解包后的行为带中，`action` 为实际采样动作，`mu` 为当时四个动作的采样概率。每张带的形状为八个健康档 × 768 个文本布局 × 八个独立副本。环境共同随机数以种子和具名随机流生成，归档保存对应字节摘要。噪声、伙伴随机数和响应均可逐步重放。每个映射目录中的 `outcomes.npz` 或 `raw.npz` 保存真实响应、行动后的健康和训练回报。在覆盖实验中，同一份响应数组服务于各个健康范围。响应值 −1 为沉默、0 为伙伴未提供维护、1 为提供维护。训练目标只读所选动作的已实现后果。

`real.npz`、`shuffle.npz`、`blind.npz` 等保存输出适配器系数。`optimization.json` 或 `fit.json` 保存各步损失、收益项、KL 和梯度范数。`probe-probabilities.npz` 以健康、保留请求／布局、四动作排列。`coverage-by-seed.csv` 汇总每个种子、条件和可见性。各条件的每个动作在每档健康的样本数、维护、死亡和平均回报保存在对应 `metrics.json` 的训练审计中。

完整生命以 `life-种子-traces.npz` 归档。键编码两位伙伴各自的偏好映射、环境副本和训练条件。列依次为情境编号、行动前健康、行动、响应、行动后健康、参考寿命变化、四个动作概率、更新前两个个人参数、所选动作的对数概率梯度、Fisher 信息、按行动前健康缩放的回报、更新后两个个人参数。零初始化的完整适配器另存 `life-种子-scratch.npz`，个人双参数的全部路径就在逐回合数组中。`singleton-lives/` 记录相同检查点以独立单条推理表示重新部署的完整生命。

六条直接执行 Qwen 的生命还有可逐行阅读的 [476 回合记录](summaries/full-qwen-encounters.jsonl)。每行包含原始请求、Qwen 所选动作及概率、伙伴回应、五次身体事件、个人参数前后值和可由该动作还原的固定模板文字。伙伴按语言行动类别回应。模板文字没有作为自由生成文本再交给伙伴模型评分。

按当前身体得出的动作变化、跨生命学到的参数、单一生命内的个人更新和不同设备运行的数值差异分别见 [主确认](summaries/confirm.json)、[完整生命确认](summaries/singleton-lives/life-confirm.json)、[训练分配确认](summaries/allocation-confirm.json)和[数值分解](summaries/numerical-factors.json)。
