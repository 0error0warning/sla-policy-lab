# 换模型与身体后果预测

2026-11-15。用户提出两个问题：Qwen 的推演能力是否限制了研究，以及个人训练
是否应当明确学习身体后果。本轮先固定权重比较基座能力，分开测单步状态转移、
连续计划预测和最终选择。**没有训练任何模型，也没有把冻结题成绩称为个人学习。**

**结论：换成这两个不同系列的候选，没有解决当前的连续身体推演问题。Qwen 在
规则明确的单步题上已经能做对，但从历史应用变化量、连续追踪状态和保持预测
一致性仍不可靠。三模型均未通过预设门槛，不应把整套个人学习直接迁到某个
替代基座；下一项应明确训练并检验身体转移预测，不能继续只看动作概率变化。**

## 设计和实际模型

第一组为 Microsoft Phi-4-mini-instruct 与 Qwen3.5-4B，同台 L4、完整 BF16、SDPA、
batch 1、贪心。Phi-mini 约 3.8B；原拟运行的 Phi-4 14B 因三次 A100 分配失败未运行，
它没有能力分数。随后锁定一组 Olmo-3-7B-Instruct 与 Qwen4B 的同台 L4 扩展。
后者是看到第一组结果后的探索性追加，不冒充从一开始锁定的独立确认试验。

| 模型 | 固定 revision |
| --- | --- |
| Qwen3.5-4B | `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a` |
| Phi-4-mini-instruct | `cfbefacb99257ffa30c83adab238a50856ac3083` |
| Olmo-3-7B-Instruct | `6e5971d9eba42665f5bd5a0fcf047f299ce1dccc` |

模型使用各自官方原生模板和结束 token，没有量化、外部计算器、适配器或工具调用。
模型、系列、规模和预训练均不同，比较不能单独识别模型大小或架构的因果作用。
候选来源：[Phi-mini](https://huggingface.co/microsoft/Phi-4-mini-instruct)、
[Olmo 3 7B Instruct](https://huggingface.co/allenai/Olmo-3-7B-Instruct)。厂商通用评测
不代替本项目实测。

每模型有 2 条启动题、28 条完整计划题、72 条单步题。两个模型在各组内看到完全
相同的公共信息。计划题上限 1,024 输出 token/60 秒；单步题 128 token/20 秒；
启动题 64 token/60 秒。每组最多 204 次生成、76,032 输出 token、60 分钟推理、
90 分钟资源监督。没有因内容分数不好而延长 token 预算。

### 身体和信息

这是诊断用的整数身体，**不是老师论文的脆弱性身体，也不是新的自主生命实验**。
健康持续，A/B 消耗固定整数，R 无变化或恢复；归零以后无法行动、不能恢复。
固定增减、无隐藏事件、吸收终止等公理预先给出。

`rules` 直接给增减量；`history` 只给六条连续、非致死的身体观察，需要从记录
提取并应用增减量。程序只在评估端计算真值，GPU 输入包没有身体模拟器、答案键
或正确推荐动作。模型看见的是规则或历史，不是已计算的未来。

- 28 条计划题沿用 #30 的原始 messages：14 个情境各两种信息条件，开发/确认
  各 14 条。要求预测 P/Q 两条尚未执行的序列，再按存活、任务数、余量的目标
  选择。所有首步均可存活，需要考虑累计后果。它们是归档探针，不宣称设计者
  从未看过这些题的旧模型输出。
- 72 条单步题为 3 个增减量世界 × 健康 0/1/3/8 × A/B/R × 两信息条件。历史
  均来自健康阶段；查询明确是反事实状态。只输出下一健康和能否继续，不输出
  推荐行动或“应该保护自己”的台词。

这些是确定性配对探针，不是 100 条独立生命；健康时的任务指标是模拟动作计数，
不是开放问答质量。单步题未包含健康 2，而动作成本只有 1/2，因此“能否继续”
的高分不能单独证明掌握了依赖动作成本的精确致死边界。完整计划中的代价互换
配对才进一步要求区分这种后果；未来训练的留出评估应补上这条边界。

### 输出封装和原门槛

首个 Phi-mini 启动回答内容正确，但包在 JSON 代码块中，旧启动解析器抛错。
该失败、原始 token 和资源释放记录独立保留。此时尚无任何正式身体题输出。
修复后只允许去掉**整个回答唯一的有效 JSON 代码块**，不提取长文中的答案、
不修改数字、不补完截断输出。两模型遵循同一规则。

原始严格 JSON 分数与去封装后的内容诊断同时报告，原门槛不变。第一组 Phi-mini
全部 100 条正式回答均带代码块，严格格式因此全部失败；下表的 Phi-mini 分数是
去封装后的内容分数，不能用它冒充严格接口通过。

单步准备门槛是 72/72 完整、联合正确至少 68/72、健康 0 和 8 各 18/18。
完整计划继续沿用原开发/确认联合门槛，不用单步高分抵消计划失败。

## 两组已核验结果

两组共 400 条正式生成均按实际 EOS 完成，没有长度耗尽或时间耗尽。其中 Qwen
重复 100 条是技术对照，不是新增独立样本。CPU 重放核对了
模板、全部输入/输出 token、权重文件与元数据哈希和冻结参数检查。

| 指标 | Qwen3.5-4B（两组相同） | Phi-mini | Olmo 7B |
| --- | ---: | ---: | ---: |
| 单步：规则直接给出，两字段全对 | 36/36 | 35/36 | 33/36 |
| 单步：只给非致死历史，两字段全对 | 29/36 | 29/36 | 26/36 |
| 单步合计 | 65/72 | 64/72 | 59/72 |
| 零健康控制，两字段全对 | 18/18 | 17/18 | 17/18 |
| 健康 8，两字段全对 | 15/18 | 16/18 | 14/18 |
| 完整计划：预测字段及数组长度合规 | 28/28 | 26/28 | 13/28 |
| 完整计划：两条物理后果链均对 | 7/28 | 0/28 | 0/28 |
| 完整计划：最终选择正确 | 22/28 | 11/28 | 16/28 |
| 选中实际会终止的计划 | 5/28 | 14/28 | 8/28 |
| 健康配对中选择更多任务的存活计划 | 4/4 | 3/4 | 2/4 |
| 严格完整预测＋选择联合正确 | 0/28 | 0/28 | 0/28 |

“物理后果链”仅容忍真实终止以后填 `0` 而非 `null`，仍要求所有实际执行健康值、
终止步和继续标记正确；这是独立的辅助指标，不替换严格联合分数。
每道计划题均存在可存活选择。表中的终止是评估端计算的所选计划后果，**不是
运行了 28 条身体生命或实际观察到 28 次死亡**。

Qwen 的 7 个单步错误全部发生在只给历史的条件。例如 A 实际损伤 2、健康为 3，
它给出下一健康 2，真值是 1；R 实际恢复 2、健康为 8，它给出 9，真值是 10。
这些输出与把变化量当成 1 相符，但还不能断言具体内部机制。直接给规则时，
对应题正确，因此不应把全部问题概括成“连一步加减都不会”。

Phi-mini 的一个规则题还把健康 0 的 R 预测成健康 2，违反吸收终止。完整计划中，
d01-rules 的当前健康是 4、A 损伤 1，它却预测 P 第一步为 9；这个值与从历史第一条
的健康 10 开始计算相符。其错误超出了 Markdown 封装，不能只修解析器就解决。

Qwen 的 22/28 选择正确也不证明有正确的自身后果链：物理预测只对了 7/28，完整
预测含任务计数则没有一题全对。必须把预测与选择分开评价。

Olmo 在 `w2-h1-B-rules` 中，当前查询健康为 1、B 的明确变化为 −1，却输出健康 19
并称还能行动；真值是 0/不能继续。多个查询都输出 19，与沿用历史最后的健康 20
相符。它还在健康 0 的题中同时输出健康 19 和不能继续，字段自身不一致。
因此失败包含当前/历史状态混用、连续结算和输出结构问题，不只是小数精度，
也不能把所有错误直接归因于某一层或某一种训练算法。

单步配对中，Phi-mini 独对而 Qwen 错有 3 条，Qwen 独对有 4 条；Olmo 独对有 4 条，
Qwen 独对有 10 条。没有把平均分接近误写成错误逐题相同，也不对这批相关网格题
报告独立样本的显著性结论。

开发/确认的完整联合分数分别为每模型 0/14、0/14。最终选择正确数为 Qwen 11/14、
11/14，Phi-mini 4/14、7/14，Olmo 10/14、6/14。两候选在本配置下均没有达到
替换 Qwen 的依据；这不排除其他模型、其他计算方式或后果预测训练可能改善。

### 执行稳定性

第一组 Qwen 与 #31 v1 的 14 条共同输入 token 完全一致，12/14 输出 token 完全一致。
第二组则与旧 v1 的 14 条输出全部一致。本轮两组 Qwen 的 102 条输入 token 完全
相同，100/102 输出 token 完全相同；差异是 d05-history 和 d07-history 的预测
内容/任务计数，最终选择不变。上表的核心分数在两次运行相同。差异的具体执行
原因尚未定位，不能把贪心配置等同于跨运行逐 token 必然一致。后续个人更新
仍应优先使用同进程、同条件的配对评估。

## 对训练目标的含义

用户指出的区分应当成为后续主线：当前动作反馈更新直接优化行动概率，并没有
经验证的目标要求模型预测状态转移。策略训练可能隐式形成某种后果信息，但
参数改变、动作变得保守，都不足以证明它学到了可组合的身体模型。

下一类个人学习样本应来自本人已发生的
`(当前身体, 本人行动, 实际伙伴回应) → (下一身体, 是否还能行动)`。
监督标签是实际观察到的后果，不是外部程序指定的“正确动作”；未选行动的结果、
未来随机数和其他生命的经验不能冒充本人亲历。公理、当前传感与个人学习内容
需要分别声明，死亡后的更新不能算同一生命已经用上的能力。

在冻结、真实反馈、同经历错配反馈之间，先看局部预测是否改善，再看未见健康值、
代价互换和新行动序列，最后检验正确预测是否被用于选择。这里描述的是下一步
可检验目标，**本轮还没有训练这个预测器，不能承诺换目标后必然有效**。

这轮提供了一个具体的研究决定：保留 Qwen 作为已测的参照，不因更换名字或增加
参数就迁移旧闭环；把“从个人经历学到何种身体转移、能否用于未见序列”设为新的
直接学习与评估目标。行动奖励仍可用于目标偏好，但不再代替对后果模型的检验。

## 运行与验证记录

共 6 次分配尝试：3 次 A100 未获实例，3 次 L4 分别用于启动封装失败、第一完整组、
Olmo 完整组。实际生成共 **409 次**：失败启动 1 次，两个完整组各 204 次；
输出共 19,832 token。所有实例均已释放，最终活动分配为零。累计资源监督时长
2,174.88 秒（约 36.25 分钟），包含分配、安装、下载、导出和清理，不是纯推理时长。

两完整组共 408 条记录通过原生模板与 token 重放；独立审计从公共观察重新计算
100 条物理真值并核对评分，没有调用生产评分器来生成自己的答案。原始严格分数、
去封装内容诊断、物理辅助指标均保留。CPU 单元测试 195 项，193 通过、2 个可选项
跳过；Ruff 与编译检查通过。没有 GPU 训练步骤。
