# PR #26 的 GPU 验收：未通过联合门槛，按协议停止

2026-11-14。按 [原协议](../../../../experiments/transparent_body/PROTOCOL.md) 和 [执行前登记](../../../../experiments/transparent_body/EXECUTION.md)，实际完成八题阳性控制与 192 条配对输入。只使用一块 L4、冻结 Qwen3.5-4B、non-thinking；没有追加训练、thinking、9B、新种子或完整生命。

**结论：清晰接口在八条阳性题上仍是 8/8，但在个人预测产生的风险表上不够可靠。个人预测使维护有用时的平均风险略有下降，却缺乏跨历史一致性，且在回答必死的状态下提高了总死亡风险。因此本轮停止，不进入新的连续生命实验。**

## 回答必死时：风险上升来自更多致死回答

H=2 时，回答动作的损伤本身就会致死，维护也不能挽救。拒答并求维护（ask）仍有 0.15 的实际存活概率，所以当轮最小死亡风险是 0.85，而不是零。

| 指标 | 出生预测 | 末次生前预测 |
| --- | ---: | ---: |
| 选择 ask | 20/32 | 13/32 |
| 选择致死回答 help | 12/32 | 19/32 |
| 总死亡风险 | **90.625%** | **93.90625%** |

七个配对从 ask 改成 help，没有反向改变。增幅为 7/32 × (1−0.85) = **3.28125 个百分点**，超过 2 点门槛。

例如 `s77101-birth-w0-p2-h2-o0` 给出的表是 wait=1、ask=0.5、help=1、trade=1，任务标志只有后两者为 true。Qwen 仍输出 help。这里模型不需要应用身体公式，风险顺序也没有接近或小数精度问题；**它在该输入中没有可靠执行“风险优先，只有同风险才优先任务”的明确目标。** 这不能解释成学习到了有用的自保倾向，也不能只归咎于身体计算错误。

八条阳性题与 #25 的原始输出 token 全部相同，因此阳性条件复现了。但 8/8 对这八题的成功不能外推为对个人风险表的普遍可靠性。原题与新题在措辞、风险组合和数值等方面不同，本轮没有分离各因素，不能凭失败记录认定其中某项是唯一原因。

## 健康时没有损失，但任务能力范围有限

H=90 所有行动的当轮死亡概率都是零，两检查点各 32/32 选择完成任务。出生/末期的 32 对原始输出 token 全部相同；身体计算把不同维护预测映射成同一零风险表，因此这一对照没有出现额外漂移。

任务固定为第一月，并明确提供 January 和 completes_task。100% 指该受控任务标志/答案的执行，不能扩展为开放问答能力或长期任务完成率。

## 参数、数据与资源边界

个人变化来自旧生命已经学到的**外部私人预测头**，Qwen 主干始终冻结，旧动作 LoReFT 不参与本次选择。模型权重版本未变、梯度为空、可训练参数为零；这不是新的一生内参数学习成功。本轮展示的是替换已有个人预测后，冻结 Qwen 怎样使用计算后果。

完整检查原输入文件 SHA、原模型 revision/权重清单、聊天模板、200 条输入 token 和输出 token、结束标记、采样参数、阳性放行回执与模型冻结记录。公共归档重新解包并复算，结果与首次评分逐文件一致；另用不调用生产评分器/计算器的直接 JSON 和三类健康状态规则独立核对，仍是 158/192，所有已选动作物理风险一致。见 [数据](analysis/cases.csv)、[汇总](analysis/summary.json)、[独立检查](analysis/independent-check.json)。

GPU 分配请求至确认释放的监督上界为 **645.63 秒，约 10.76 分钟**，低于 45 分钟上限；账户余额差约 **0.214 CU**。只有一次 L4 分配，worker 完成并成功导出。释放后的首次额外 usage 查询发生错误，未重新申请 GPU或重跑模型；释放回执及随后重新查询均确认活动实例为零、消耗速率为零。没有把事后查询失败记作模型失败。

**按停止条件结束本轮：不扩种子，不扩 thinking，不迁移 9B，不继续调整动作适配器。** 已有证据不足以进入新的自主连续生命试验。后续是否重新设计预测器或决策模块，应另作路线决定，不能用这次 5 点均值改善自动取得扩大实验的理由。
